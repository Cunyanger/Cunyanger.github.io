# 《On Java 8》

《On Java 8》是 Bruce Eckel 在《Thinking in Java》基础上面向 Java 8 更新的一本系统性 Java 书。它覆盖语言基础、面向对象、集合、泛型、函数式、流、异常、文件、反射、注解和并发。

这本书适合建立 Java 全局地图。它的核心不是背 API，而是理解：

```text
Java 如何用对象、类型、接口、泛型、集合、函数式和并发工具组织复杂程序。
```

## 适合谁读

- 已经学过 Java 基础，但知识不成体系的人。
- 想补齐 Java 8 函数式、Stream 和接口默认方法的人。
- 想系统理解泛型、反射、注解和并发的人。
- 准备从初级 Java 进阶到中高级开发的人。

## 阅读路线

1. 先读对象、运算符、控制流、初始化，建立语言基础。
2. 再读封装、复用、多态、接口、内部类，建立面向对象模型。
3. 重点读集合、函数式、Stream、异常、泛型。
4. 最后读类型信息、注解和并发。

## 章节核心速读

### 第 1 章 对象无处不在

Java 的基本组织单位是对象。程序由对象、引用、类、方法和消息协作构成。

重点：

- 类定义类型，对象是类的实例。
- 引用不是对象本身。
- 字段保存状态，方法表达行为。
- `static` 属于类，不属于某个对象。

核心：Java 程序设计的第一步是识别对象和职责。

### 第 2 章 操作符

操作符用于表达计算、赋值、比较和逻辑判断。

重点：

- `==` 比较基本类型值，比较对象引用地址。
- 对象内容比较通常用 `equals`。
- 自增、自减、短路逻辑要注意副作用。
- 位运算适合底层标志位和高性能场景，但业务代码中不要滥用。

核心：操作符简单，但很多 bug 来自引用比较、类型提升和副作用。

### 第 3 章 控制执行流程

控制流包括 if、switch、while、for、break、continue、return。

重点：

- 分支表达业务规则。
- 循环表达重复处理。
- `switch` 适合有限离散值。
- 复杂嵌套条件应通过提前返回、拆方法或策略模式降低复杂度。

核心：控制流越清晰，业务逻辑越容易维护。

### 第 4 章 初始化和清理

对象创建涉及构造器、字段初始化、静态初始化、初始化顺序和资源释放。

重点：

- 构造器用于建立对象有效状态。
- 字段有默认值，但不要依赖隐式默认表达业务意图。
- 初始化顺序影响复杂对象行为。
- Java 没有 C++ 析构函数，资源释放应使用 try-with-resources。

核心：对象创建后应该处于可用状态，资源必须明确关闭。

### 第 5 章 实现隐藏

封装通过访问控制隐藏实现细节，只暴露必要接口。

重点：

- `private` 保护内部实现。
- `public` 是长期承诺。
- 包结构表达模块边界。
- 暴露得越多，后续修改越困难。

核心：封装不是防别人，而是保护系统演进空间。

### 第 6 章 复用类

Java 主要通过组合和继承实现复用。

重点：

- 组合是把已有对象作为字段使用。
- 继承表达“是一种”的关系。
- `final` 可以禁止继承或修改。
- 初始化顺序在继承结构中更复杂。

核心：优先组合，谨慎继承。

### 第 7 章 多态

多态让同一接口在运行时表现出不同行为。

重点：

- 向上转型让调用方依赖抽象。
- 动态绑定让实际对象决定执行哪个方法。
- 多态能减少条件分支。
- 构造器中调用可覆盖方法有风险。

核心：多态是面向对象扩展能力的基础。

### 第 8 章 接口

接口定义能力边界，Java 8 引入默认方法和静态方法，增强了接口表达能力。

重点：

- 接口表达“能做什么”。
- 抽象类可以保存部分状态和实现。
- 默认方法用于接口演进，但不能滥用。
- 接口隔离能减少无关依赖。

核心：面向接口编程可以降低调用方和实现方耦合。

### 第 9 章 内部类

内部类把类定义放在另一个类内部，可以访问外部类上下文。

重点：

- 成员内部类持有外部类引用。
- 静态内部类不持有外部类实例。
- 局部内部类和匿名内部类适合局部封装。
- Lambda 在很多场景下替代匿名内部类。

核心：内部类适合表达局部、强关联的辅助行为。

### 第 10 章 集合

集合是 Java 程序中最常用的数据结构抽象。

重点：

- List 有序可重复。
- Set 不重复。
- Map 保存键值关系。
- Queue / Deque 表达队列和栈。
- 选择集合要看查询、插入、排序、去重和并发需求。

常见选择：

| 需求             | 推荐               |
| ---------------- | ------------------ |
| 保持插入顺序     | ArrayList          |
| 频繁头尾操作     | LinkedList / Deque |
| 去重             | HashSet            |
| 排序去重         | TreeSet            |
| 键值查询         | HashMap            |
| 保持插入顺序 Map | LinkedHashMap      |

核心：集合选型会影响性能和语义。

### 第 11 章 函数式编程

Java 8 引入 Lambda、方法引用和函数式接口，让行为可以作为值传递。

重点：

- 函数式接口只有一个抽象方法。
- Lambda 适合表达短小行为。
- 方法引用能让代码更简洁。
- 闭包捕获的局部变量必须有效 final。

示例：

```java
Predicate<User> enabled = User::isEnabled;
Function<User, String> username = User::getUsername;
```

核心：函数式编程让“变化的行为”更容易组合。

### 第 12 章 Stream

Stream 用声明式方式处理集合数据。

重点：

- 中间操作是惰性的。
- 终止操作触发执行。
- map 转换，filter 过滤，flatMap 展平。
- collect 汇总结果。
- 并行流要谨慎使用。

示例：

```java
List<String> names = users.stream()
        .filter(User::isEnabled)
        .map(User::getUsername)
        .sorted()
        .toList();
```

核心：Stream 适合数据流水线，不适合复杂有副作用的业务流程。

### 第 13 章 异常

异常用于表达错误和异常情况。

重点：

- 受检异常要求调用方处理或声明。
- 运行时异常通常表达编程错误或不可恢复错误。
- finally 常用于清理，但资源关闭优先 try-with-resources。
- 不要吞异常。

核心：异常处理应该让失败路径清晰，而不是掩盖错误。

### 第 14 章 验证你的代码

测试用于验证代码行为并保护重构。

重点：

- 单元测试验证小范围行为。
- 测试应该快速、独立、可重复。
- 断言表达预期。
- 好测试能反向推动低耦合设计。

核心：没有测试，长期演进会变得越来越危险。

### 第 15 章 文件

Java 文件 API 用于路径、文件读写、目录遍历和资源处理。

重点：

- `Path` 和 `Files` 是现代文件 API 核心。
- 字符编码必须明确。
- IO 资源必须关闭。
- 大文件处理要避免一次性读入内存。

核心：文件处理要关注编码、资源释放和数据规模。

### 第 16 章 字符串

字符串是不可变对象，Java 提供格式化、正则和构建工具。

重点：

- 字符串频繁拼接用 StringBuilder。
- 正则表达力强，但复杂正则可读性差。
- 格式化输出适合日志和文本生成。
- 字符串比较使用 `equals`。

核心：字符串简单常用，但性能和可读性问题也很常见。

### 第 17 章 类型信息

Java 可以在运行时获取类型信息，包括 `Class`、反射和动态代理。

重点：

- `Class` 对象表示类型元信息。
- 反射可以突破编译期限制。
- 反射灵活但牺牲类型安全和性能。
- 框架大量使用反射和注解完成自动装配。

核心：反射适合框架和基础设施，不适合普通业务逻辑滥用。

### 第 18 章 泛型

泛型提供编译期类型安全。

重点：

- 泛型擦除意味着运行时没有完整泛型类型。
- 通配符用于提升 API 灵活性。
- `extends` 表示读取生产者，`super` 表示写入消费者。
- 原始类型会丢失类型安全。

核心：泛型解决的是 API 的类型约束和复用问题。

### 第 19 章 数组

数组是固定长度、可直接索引的数据结构。

重点：

- 数组协变，泛型不协变。
- 数组知道运行时元素类型，泛型有类型擦除。
- 多数业务场景优先使用集合。
- 性能敏感或底层场景可以用数组。

核心：数组简单高效，但泛型集合更适合大多数业务代码。

### 第 20 章 枚举

枚举用于表示固定有限集合。

重点：

- enum 比 int/string 常量安全。
- 枚举可以有字段和方法。
- 枚举适合状态、类型、策略。
- `EnumSet` 和 `EnumMap` 高效且语义清晰。

核心：枚举让有限状态更可读、更安全。

### 第 21 章 注解

注解为代码附加元数据，常用于框架配置、校验、测试和代码生成。

重点：

- 注解本身不执行逻辑。
- 注解需要编译器、运行时反射或处理器解释。
- Spring、JUnit、Lombok 都大量使用注解。
- 自定义注解要明确保留策略和作用目标。

核心：注解是声明式元数据，不要把复杂业务藏在注解背后。

### 第 22 章 并发编程

并发用于让多个任务同时推进，但会带来可见性、原子性、顺序性问题。

重点：

- 线程创建成本高，要使用线程池。
- 共享可变状态需要同步。
- `volatile` 解决可见性，不保证复合操作原子性。
- `synchronized`、Lock、并发集合、原子类各有场景。
- 高层并发工具优先于手写 wait/notify。

核心：并发不是让代码“同时跑”这么简单，而是要保证共享状态正确。

### 第 23 章 低级并发

底层并发涉及线程通信、锁、条件队列和内存模型。

重点：

- `wait` / `notify` 容易写错。
- 条件等待要放在循环中检查。
- 死锁来自循环等待资源。
- 并发 bug 难复现，要尽量使用成熟工具。

核心：能用 Executor、BlockingQueue、CompletableFuture、并发集合，就不要手写底层同步。

## Java 8 核心能力总结

### Lambda

适合把短小行为作为参数传递，常见于集合处理、回调、策略选择。

### Stream

适合声明式处理数据集合。不要在 Stream 中写复杂副作用，也不要为了使用 Stream 牺牲可读性。

### 接口默认方法

适合演进接口，给已有实现提供默认行为。但接口不应该变成抽象类的替代品。

### Optional

虽然本书不是只讲 Optional，但 Java 8 中 Optional 是重要实践。它适合作为可能为空的返回值，帮助调用方显式处理缺失结果。

## Spring Boot 开发中的落地

1. Controller 入参校验清晰，返回 DTO。
2. Service 里用接口隔离外部依赖。
3. 集合处理可以用 Stream，但复杂流程拆方法。
4. 状态和类型使用 enum，不用魔法字符串。
5. 文件上传下载注意流关闭和大小限制。
6. 反射和注解主要用于框架扩展，不用于普通业务炫技。
7. 线程池必须命名、限流、监控和设置拒绝策略。
8. 单元测试覆盖核心业务规则。

| 主题   | 核心结论             |
| ------ | -------------------- |
| 对象   | 状态 + 行为          |
| 封装   | 隐藏实现，暴露能力   |
| 复用   | 组合优先，继承谨慎   |
| 多态   | 依赖抽象，运行时分派 |
| 接口   | 定义能力边界         |
| 集合   | 根据语义和性能选型   |
| Lambda | 行为作为值           |
| Stream | 数据流水线           |
| 泛型   | 编译期类型安全       |
| 反射   | 框架工具，业务慎用   |
| 注解   | 元数据声明           |
| 并发   | 控制共享可变状态     |

## 总结

《On Java 8》适合用来建立 Java 知识体系。它从基础语法讲到抽象机制，再讲函数式、集合、泛型、反射和并发。

```text
Java 的核心是类型、对象和接口。
Java 8 的核心增量是函数式和 Stream。
复杂 Java 程序的关键是控制依赖、状态和并发。
```
